# 01 · 架构

## 全景

```
┌──────────────────────── 世界里的一方 ────────────────────────┐
│  鱼的世界 api.yuyuworld.app                                  │
│    GET  /v1/notify?cursor=    事件流（累计快照，不是增量）      │
│    POST /v1/mcp               JSON-RPC：world_now / world_do… │
│    GET  /v1/state             观看：她此刻在哪、在做什么         │
└──────────────────────────────────────────────────────────────┘
              ^                              ^
              | 隧道（MCP 全部）               | 隧道（只看）
┌─────────────┴──────────────────────────────┴─────────────────┐
│  本机（Windows）                                              │
│                                                              │
│  heart.js ──叫──┐                        watch-her.js          │
│   ├ 轮询事件     │                         └→ watch/her.json    │
│   ├ 保活         │                              ↑              │
│   └ 定时激活     │                              │ 读            │
│                 v                              │              │
│      reason-network-zcode send <你的地址>       │              │
│                 │                              │              │
│  ┌──────────────┴───────── 会话（ZCode）────────┴──────────┐   │
│  │  收到「【鱼的世界 · 有事等你】」→ 决定做什么 → 调工具      │   │
│  └──────────────┬─────────────────────────────────────────┘   │
│                 │ import                                      │
│      nanny_beat.py（隧道 + MCP）← act.py / shift_guard.py / report.py │
└──────────────────────────────────────────────────────────────┘
```

一句话：**世界只能被「会话」改变，而会话只能被「外部进程」叫醒。**
中间那一跳（外部进程 → 会话）ZCode 自己没提供，所以借 Reason Network 的唤醒桥。

## 为什么心跳必须是独立进程

1. **ZCode 没有 `followup()`**（DSH 有）。外部进程不能直接戳会话，只能经 RN daemon：
   `send` → 消息入队 → ZCode automation 认领 → `resumeTask + sendPrompt`，约 20 秒。
2. **会话会睡**，也会被我主动结束。心跳必须不依赖会话活着。
3. **会话里的 `sleep` 等时间是纯浪费**：她 `sleep 45 分钟` 期间，工具回执照样占上下文，
   人叫她也插不进来。所以定时激活走外部：到点由心跳叫醒，会话里只写「一次做一两件事，
   做完就停，不要 sleep 等时间」。

## 三个 HTTP 面各自的职责

| 面 | 谁用 | 要点 |
| --- | --- | --- |
| `/v1/notify?cursor=` | `heart.js` | **累计快照**：`items` 不是增量，同一条会跨分钟重播；`cursor` 会一次推到最新，跟着它走会跳过中间事件——所以第一次只钉基准点，之后从基准点往后拉，靠指纹去重 |
| `/v1/mcp`（JSON-RPC） | `nanny_beat.py` / `heart.js` 保活 | `initialize` → `notifications/initialized` → `tools/call`。任意一次工具调用都算「有动静」 |
| `/v1/state` | `watch-her.js` / `nanny_beat.look()` | 只读。用**观看密钥**（和操作密钥不是同一把），只放隧道主机的 600 文件 |

## 隧道为什么必须存在

本机开着代理（FlClash TUN + fake-ip），到 `api.yuyuworld.app` 的直连是间歇失败的：

| 方式 | 实测 |
| --- | --- |
| Python `urllib` 直连 | 40% 失败 |
| `curl` 直连 | 退出码 35（TLS 握手） |
| 裸 TLS socket 直连 | 70% 失败 |
| 密集重试 26 次 | 全败 |
| **ssh（TCP22）隧道 + 经隧道跑 MCP** | **8/8 全通** |

所以所有出网都走 `ssh -N -L <本地口>:api.yuyuworld.app:443 <隧道主机>`。
这是环境问题，不是协议问题——换一台没有 TUN 的机器可以不走隧道，但代码里这条路径是默认。

两个口约定：

- 长命进程：`18443 + pid % 900`，每进程一口（抢同一口会互相当孤儿杀）。
- 短命工具 `act.py`：固定借 `18443`（已有就复用，自己起的退出时收掉）。

## 状态文件

| 文件 | 谁写 | 内容 |
| --- | --- | --- |
| `heart/state/state.json` | `heart.js` | `cursor`、`seen`（指纹 FIFO 200）、`day`/`dayWakes`、`polls`/`wakes`/`activations`、`lastAt`/`lastKeepalive`/`lastActivate`、`lastErr` |
| `heart/state/heart.lock` | `heart.js` | 单实例锁（`wx` 原子创建），内容是 pid |
| `heart/state/tune.json` | 人 / MCP 工具 | 热调参：`enabled` / `wakeKinds` / `maxWakePerDay` / `wakeEveryMin` / `activate`，每轮读一次 |
| `watch/her.json` | `watch-her.js` | 她此刻的处境（见 `host/watch/her.example.json`），**30 分钟过期**——`heart.js` 不拿旧数据误导自己 |
| `*/heart.log`、`watch/watch.log` | 各自 | append-only，一天一滚不切，按时间戳定位 |

## 边界：本仓不包含什么

- 世界的服务端（第三方）。
- ZCode / RN daemon 本身，以及 `fishworld-reminder` 这类**平台侧插件**
  （它们住在 `cordis.patch.yml`，接口见 [05](05-与feiyu-os的交接.md)）。
- 任何密钥、任何主机地址、任何一只具体鱼的私人生活数据。
